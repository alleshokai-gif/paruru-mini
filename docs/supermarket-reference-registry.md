## Reuse without another interpretation/model call

`registerReferenceArtifact(db, packet, {sourceDb})` accepts an already-created
reference packet only after matching the saved 00521 source document, both saved
page URLs/hashes, original acquisition time and printed edition interval. The
registry key includes store, issue and the existing page-based source revision;
it excludes the daily observation clock. The packet remains immutable. Same-key
different input, altered registry contents or corrupt canonical rows are refused.
No original image is copied into the registry.

`collectIy(..., {referenceArtifactsEnabled: false})` is **OFF by default**.
Existing `runDaily` does not pass this option; no environment/config flag or
enabled production lane was added. Only an explicit local test uses `true`.
After normal discovery, the opt-in branch can import the registered exact source
revision using the existing corpus store. It cannot start a worker, model or
additional source request. Unregistered new editions remain unanalysed; an old
artifact is never rebound to a new hash, source, acquisition time or issue.

Registration and application have separate immutable records. Canonical corpus
insertion is atomic; if interrupted before its receipt, exact readback recovers
the existing corpus without another model call or duplicate rows. Original
tables, images, status claims and history are not deleted or replaced. Applying
references never creates confirmed offers, fills missing item dates, or refreshes
acquisition time. Edition expiry stops reuse; item-day filtering remains in the
existing Gateway/UI projection. The registry does not certify name, price, unit,
conditions or individual validity.

## Evidence and remaining prerequisites

Fictional tests enter `collectIy` itself and cover default OFF, exact registered
reuse, next-day same-hash zero insertion, missing/new edition, changed face,
wrong store, expiry, immutable conflict and readback drift. They do not run a
model or contact a source. The actual existing 151-row interactive artifact was
registered/applied in a separate local DB: 151 reference rows, repeat 0, confirmed
offers 0, original source/prior DB unchanged and expiry suppressed. This is
registered-result reuse, not new-issue extraction or production acceptance.

Before production, establish a formally supported zero-additional-charge mode
or account contract for the owner-authorized experiment; otherwise keep the
model stopped. Separately prove authorized durable image retention, source
discovery within existing capacity limits, real daily invocation and current
edition validity. Neither registration nor this opt-in API authorizes production
settings changes. Keep the production lane OFF and do not publish the historical
51325 specimen as a future current issue.
